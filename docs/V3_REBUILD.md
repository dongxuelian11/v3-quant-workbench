### 2. 每日研究台与成果管理

独立项目负责研究，每日研究台负责使用成果。

- 新项目提供因子、策略、模型、课题和研报复现起点，按用途安排页面；因子研究不强制创建策略，项目后续可以扩展。
- 每日研究台管理多份命名方案，引用不同项目的因子、策略、模型和筛选成果。支持分别运行或一键运行选中方案。
- 引用固定成果版本。原项目更新后展示差异和验证结果，由用户选择采用；每次运行保存实际版本。
- 因子支持每日观察、股票筛选、策略评分、持仓暴露及归因。研究结论、数据覆盖和模型重要性分别展示。
- 模型固定特征、算法与参数；手动运行方案时，按每月首次运行规则使用当时可用数据重训，保存模型与训练记录。自动重训不包含寻优。
- 多策略独立保存结果，按用户配置的资金占比合并目标组合，再应用整体约束。生成清单不修改实际持仓。
- 默认首页为“研究简报＋联动详情”：展示数据截止日、方案状态和关键变化，点击后联动因子趋势、股票行情、组合或实验比较。各方案记住适合自身用途的视图。
- 保留项目左栏、大图表、可收起的 AI 右栏和干净启动；启动不自动计算。重计算默认排队，下载与读取适度并行，优先保持操作流畅。独立方案失败不阻断其他方案，有依赖的步骤停止等待处理。
- 因子有效性同时呈现历史样本外结果与版本确定后的新增数据表现；未走完收益观察期的信号显示“等待评价”。异常只形成证据与建议，不自动停用因子或修改权重。

### 3. 数据与量化可靠性

按数据与时间正确性 → 成交与账户正确性 → 统计有效性补强，发现明确计算错误立即修复。

#### 数据准备与复现

- 提供沪深全市场目录和近期行情，研究历史按股票池、字段和日期补齐，不要求先下载全市场多年数据。
- 免费源与文件导入优先。覆盖说明区分当前上市、退市证券、历史成员、行业、财报公告和公司行动；缺少的数据不以当前记录回填。确需付费来源时先列出具体缺口、覆盖和费用，由用户决定。
- 正式研究缺少关键条件时停止受影响步骤，提供补数据或缩小范围等选择。探索实验允许采用用户明确选择的替代方法，保存差异；任何模式都不允许未来信息进入历史信号。
- 实验保存实际使用的数据切片、配置、公式／代码、随机种子及相关依赖版本。共享不可变快照，修改数据生成新快照，不重复复制整套数据库，不建立哈希身份链。
- 支持按原数据复现和按最新数据重算。记录更新时间及受影响范围，只重算相关步骤，旧结果保持不变。
- 显示项目、实验与快照占用，提供手动批量清理。被引用的成果与复现材料不进入普通清理清单；仅删除没有其他引用的快照。历史任务清理不删除实验。

#### 成交与验证

- 核对财报可知时间、历史股票范围、复权和公司行动、标签边界，明确无法可靠研究的区间。
- 核对现金、持仓、费用、历史印花税、滑点、停牌涨跌停、申报数量和未成交原因；回测与模拟账户共用口径。
- 提供更高滑点、更低历史成交量参与上限和延迟执行的压力对比。暂不引入未经校准的市场冲击模型。
- 默认单次时间切分，候选再进行滚动验证。测试区间不参与选参；看过测试结果后继续修改，保留该区间已被使用的记录。
- 因子以主股票池形成主要结论，同时提供市值、行业和市场阶段对照，使用当时可知的分类。
- 成果提供证据摘要：样本外表现、稳定性、成本敏感性、数据缺口及尝试过的方案数量。由用户决定用途，不设置统一收益门槛；自定义筛选标准留待后续。

### 4. AI 与研报研究

#### AI 执行

- 条件明确的执行指令直接调用现有研究工具；宽泛请求先形成可编辑方案，确认后连续执行依赖步骤，读取真实结果再讨论下一阶段，不逐步审批。
- 每份开放研究方案默认最多三轮、6 组候选实验、每次寻优 20 次试参、30 次模型请求。方案列出必要的基准、验证和压力计算，并显示预计总计算范围。
- 上限可在确认前修改，不要求跑满。模型重试及 RD-Agent 内部请求计入预算；达到预算保存进度，不自行扩大研究。不能可靠估算费用时明确说明。
- 保留取消、阶段间补充消息和失败恢复。恢复不重复提交已完成任务；代码失败沿用保存错误、提出修复、用户确认后继续的方式。
- 每日研究会话默认读取当前方案引用的成果、摘要和实验依据，可按需检索其他项目并说明来源；不会把所有历史聊天混入上下文。增加引用、替换版本先提出建议。
- 独立项目会话继续隔离；发送时固定项目和引用，延迟回复返回原会话。
- 先验证已配置服务；仍不稳定时提出替代模型与费用，由用户选择后再对比，不自动切换服务。

#### 研报闭环

- 优先收集量化方法研报，兼顾策略与行业研究，个股报告保留检索和导入。主题订阅与主动检索作为日常入口。
- 复用现有 SQLite 全文检索、PDF.js、文本解析和按需 OCR，实际填充用户研报库。订阅仅自动收集目录和可获取原文，不自动调用 AI 或发起实验。
- 先走通指定报告复现，再完善围绕研究问题的跨报告检索与证据比较。
- AI 按页码提取原文条件，集中列出公式疑点、缺失条件和替代方案。用户一次确认后连续执行，原文规定与补充假设分别保存。
- 保留原文复现、适配实验、发布后验证和现实成交检验的区别；非量化观点先转成待验证假设，不直接生成交易信号。
- OpenUI 展示可编辑方案和实际实验结果；保存表单与运行引用，重开历史不重新执行。
- 复现成果随项目保存，可被每日研究方案引用固定版本。

### 5. 实现、验证与协作

在 `packages/contracts/src/research.ts` 扩展必要类型：每日方案、固定成果引用、数据快照引用、证据摘要和研究预算。项目增加研究起点，实验增加数据与前置结果引用；沿用现有任务、会话、候选库和研报接口，不建立另一套执行系统。

每日方案保存在全局存储，项目继续保存研究与成果；跨项目引用使用项目、成果及版本标识。旧实验正常打开，缺少快照或验证证据的字段明确显示不可用，不补造历史材料。旧启用策略保留原配置，提供导入每日方案的入口，不自动引用其他项目。

验证集中覆盖：

- 实际用户环境：全市场目录可用，明确区分目录与历史覆盖；选定研究范围后自动补齐，缺口处理和文件导入有效。
- 量化小样本：历史范围变化、公告日期、标签边界、公司行动、费用、现金持仓和成交限制；原数据复现与最新数据重算区别正确。
- 日常流程：因子／课题起点 → 实验 → 证据摘要 → 固定版本引用 → 多方案运行 → 股票与组合联动 → 导出 → 模拟账户。
- 成果变化：新版本提示、月度重训、未成熟信号、异常建议、引用保护和快照清理。
- 真实 AI／研报：原文引用、一次确认后连续运行、预算统计、取消恢复、项目隔离、OpenUI 历史不重跑；离线回放不替代在线成功。
- 安装版：新环境与旧项目升级、窗口自适应、侧栏记忆、后台操作和已知阻断问题复查。

沿用可见的前端、后端和独立 QA 任务，使用 Astra low；主任务负责接口、整合和沟通。实施时只更新 `docs/V3_REBUILD.md`。普通修改检查相关行为，集中验证后只复查受影响部分，不增加例行哈希、逐功能审批或反复全量测试。
