## 三、研究功能与数据规则

### 1. 数据、性能与初始化

- 启动界面不依赖 Python 成功启动；普通用户无需执行 npm／pip。
- 基础量化环境随安装交付；AI、OCR、TDX、RD 等可选能力按需配置。
- 首次研究使用来源明确、可分发的固定真实小样本，由实际引擎运行。
- 首次可选择准备沪深近两年基础数据；不在启动时自动下载全市场，更早历史按需获取。
- 已有资料可继续使用，也可新建干净资料目录；保留旧资料，不自动继承密钥和会话。
- 行情、历史成员、行业、公告财务和公司行动分别管理；不能用今日名单回填历史，不能从复权价猜公司行动。
- 运行前固定行情及预热、日历、成员、财务、公司行动、基准等实际输入；复用不可变分区或必要切片，不复制整库。
- 原输入复现与最新数据重算分开，均另存实验；缺失不填零。
- 首屏先读取摘要与有限预览；图表按视口抽样，统计和完整导出使用完整数据。
- 导入 CSV／Excel／Parquet 先预览字段、单位和复权口径；默认补缺，冲突替换需明确选择。按文件验证，失败文件可单独重试。
- 数据目录迁移检查空间、暂停受影响写入、复制验证后切换，保留旧目录。
- 清理仅针对未被引用、可重建的缓存；项目包按选择打包输入和成果，不带密钥或整库。

### 2. 行情、指标、因子、模型与回测

- 可见行情默认每 60 秒刷新，保持视口、排序和画线；市场概况提供当日、近 5／20 交易日。
- 保留 TDX880823 来源身份；替代指数必须独立命名，不冒充原曲线。
- 自定义 N 日周期采用固定交易日锚点；未完成周期不能作为历史已确认信号。
- 分钟数据用于观察；分时均价只有在来源或量额口径完整可核对时计算。
- 保留 MJ 原公式及 M1=5、M2=20、M3=60、M4=10，独立核对量额单位、累计起点和复权。
- 数值输出、隐藏命名条件可用于筛选和研究；绘图指令不作为因子值。
- 指标可直接选择买卖条件进入回测，不强迫先建因子。
- 收盘确认信号，下一交易日尝试执行；信号策略持有至退出，不被高分新股自动挤出。
- 总仓位按最大持仓数分份，不足留现金；重复买点默认忽略，退出优先；超出空位时使用明确选定的排序。
- 回测与模拟账户共用原始价格成交、历史税费、手数、停牌涨跌停及公司行动规则。
- 选中 K 线查看该实验原输入下的条件、约束、订单与成交原因。
- 因子分析区分分组、IC／RankIC、归因和重要性；缺样本时如实显示不可用。
- 模型默认时间切分 70／15／15，可修改；训练配方与模型产物分开，验证选参，测试集独立。
- 风险平价、均值方差等沿用选定上游能力；约束不可满足时说明原因，不偷偷放宽。
- 批量实验与寻优保留已完成结果，仅重试未完成项；候选采用由用户明确操作。

### 3. 选股、每日研究与模拟账户

- 选股独立于项目；支持条件组、不同周期、时序条件及因子评分，排名参照范围明确。
- 展示范围、有效、入选和无法判断数量；可查询未入选原因。
- 自选默认追加去重并保留备注；替换名单独立操作。
- 每日研究固定方案版本，源更新展示差异，由用户采用；进入页面不自动运行。
- 月度按需重训失败暂停对应方案，使用兼容旧模型须明确选择。
- 方案 A 失败不阻止独立 B；合并结果标记不完整，不把 A 的资金自动分给 B。
- 模拟账户全局独立，可有多个；入出金不计为收益，提款不自动卖股。
- 手工持仓默认手工管理；未成交订单当日到期。
- 多策略保留资金与成交归属；冲突需要处理时不阻塞无关证券。
- 停用策略默认停止新开仓，原持仓继续旧退出规则；移交手工或清仓分别操作。
- 策略升级后旧持仓沿用原规则，新持仓使用新规则，不重复买入同一已有标的。
- 历史错误通过新账户分支按原时点输入重放修正，保留原账户和原记录。
- 提醒支持单证券与明确的自选快照；价格用有效报价、指标用完成周期。缺数据不猜测，程序未运行时不声称持续监控。

#### 提醒完整流程：来源核对与待定口径（2026-09-24）
- 当前公开接口和页面尚无提醒创建到触发记录的完整链。现有自选组保存、结果追加/明确替换、选股提交时冻结名单可复用，不能算提醒已实现。
- 用户已明确选择：盘中和收盘均支持，创建时选择；分钟收盘价必须明确标识，不冒充逐笔报价。
- 后端静态核对：东财全市场快照缺完整源报价时间；新浪快照时间戳可能只有时分秒。采集时间、缓存updatedAt和ready均不能充当有效报价证明。现有单证券1分钟接口可保留源日期与时间，但含义是minute_close，非last_trade；没有实连验收。官方AKShare文档版本与已安装版本不同，具体字段仍须实装核验。禁止为单证券提醒轮询全市场四线程快照。
- 收盘观察须共同核对目标交易日、真实交易日历覆盖、数据日期、来源刷新结果；今日未发布时明确无法判断，不拿昨天收盘价顶替。日历缺失不靠周末推断，也不静默切换用户选择的数据源。
- 完整流程目标：单证券或用户确认的固定A股名单（保留来源组身份/名称/时间）→创建规则与版本→手动检查及启用后的运行中串行检查→逐证券触发/未触发/无法判断及原因→可回看的观察与触发记录→暂停、恢复、删除。原自选编辑不改变已确认范围；应用关闭期间不监控、不伪造补发记录。
- 实现约束：观察明确区分来源时间、交易日期、采集时间、价格含义与有效性；价格必须有限且正数。相同观察去重，持续满足不重复通知，明确重新不满足后再满足才重新触发；无法判断不重置已满足状态。来源错误、过期、缺日历、未完成周期分别说明，不猜停牌。
- 指标提醒仍在完整计划另批实现。现有complete标记尚不足：分钟周期语义、周/月节假日边界、自定义周期缺中间交易日均需核对后再计算；不另建指标引擎。
- 价格模式已确认，真实报价适配仍待实现。主任务已定ReminderScopeSnapshot/Rule/Observation/Check/Runtime契约；先实现固定名单确认、规则版本与幂等保存、暂停/删除、检查历史和诚实不可用状态，再串行接管理界面。未选口径或缺有效来源时不可启用触发，不伪造报价。完整提醒闭环尚未验收，指标和真实价格检查均保留后续接线。


### 4. AI、研报与开源研究循环

- 修改草稿可撤销；明确执行才提交任务。开放研究确认阶段方案后连续完成依赖步骤，不逐步审批。
- 默认每阶段最多三轮；全计划共用 6 个候选、20 次试参、30 次模型请求，重试计入预算，计算任务另列。
- 首次代码失败保留证据与检查点，给出修复方案后按既定确认流程继续；临时网络故障最多重试两次，不自动换模型。
- 长研究期间允许其他会话问答；新长研究排队，回复与结果始终归原项目和会话。
- 中途补充在确认处理成功前保持待处理；取消或失败不吞掉补充。
- 上下文压缩保留完整历史及明确决定、禁止事项、预算、阶段与待处理内容；不假定所有服务支持同一种压缩协议。
- 项目反思限定项目范围，保留来源、日期和相反证据，不静默改写交易规则。
- TradingAgents 用于首次实验前与最终结论的质疑审查；意见不等于回测结果，计入研究预算。
- LangAlpha 借鉴研究工作区、产物与上下文管理机制，不整体引入其数据库、调度和独立平台。
- RD-Agent 承担新因子／模型探索；普通研究直接调用既有工具。
- 研报本地全文优先；联网搜索与获取在研究方案中明确，保留来源和时间。摘要不冒充全文，付费或登录失败如实说明。
- OCR 按需启用，不猜不清楚的公式；结论分支持、不支持、无法判断，关联原文页码与实验。
- 原文复现、适配、发布后验证、现实成交检验分别记录；独立可执行部分在确认范围后继续。
- OpenUI 展示实际成果，重新打开不运行任务。
- 本地助手处理查找、导航和明确草稿编辑，不静默转在线模型；普通搜索不依赖模型。单实例、闲置十分钟释放，不阻塞日常版本交付。

## 五、验收与交付条件

- **工作区：** 实际点击两个顶栏按钮，验证四种展开组合、中心扩展、宽度恢复、窄窗口及键盘操作；切换不丢草稿、视口、画线或会话。
- **研究主流程：** 真实数据完成指标→规则→回测→交易原因→比较→导出，核对原输入和成交口径。
